# Private campaign provisioning contract

`provisionCampaignProject(env, principal, resolvedOwner, input)` in `campaign-provision.ts` is an administrator-only helper for F's `POST /api/admin/campaign/provision` route. F normalizes `input.username` with the existing account function and supplies it as `resolvedOwner`; the helper checks both administrator authority and an existing active reviewer workspace. It creates no account, provider connection, campaign approval or run.

Input fields are `username` (optional matching owner), `repo_id` (exact safe target), `template` (existing safe Artifacts repository name), `policy` (frozen core policy), optional `context_study` and optional `context_seed`. Other fields, including public source URLs, are rejected. The operator-created template is `yoneda-booking-campaign-starter-20261012`; its contents must be the incomplete starter intended for the campaign. `policy.build.app` is optional for study repositories.

`context_study` follows the Rust study contract. `context_seed` is `{intent_id, statement, records}` using standard typed ContextInput IDs, for example `intent:booking-study` and `context:booking:capacity`. Both pass unchanged into authoritative Rust `init`, which validates and creates owner assertions atomically without jobs. The helper does not configure an existing study arm.

Return value is `{username, repo_id, status, commit, source}` where status is `ready` or `provisioning`, commit is the frozen starter HEAD, and source is `{namespace, name, branch, commit}`. No token or remote URL is returned. The caller can use HTTP 202 for provisioning and repeat exactly the same body.

The helper reads trusted Artifacts metadata/default-branch log, freezes input plus source at private create-only R2 `campaign-provision/<repo_id>.json`, and initializes the repository ledger under the resolved owner. Rust validates policy/study/seed before the external fork. It forks only to the exact target name, verifies source ancestry metadata and unchanged initial HEAD, and revokes initial active Git capabilities. Then it uses `project_reserve`, `project_claim` and `project_update(status: ready)` with the setup epoch so the existing account's UI lists the new project. There is no `project_ready` command in the current contract.

Unowned existing ledgers/remotes are rejected. Changed owner, target receipt identity, template, policy, study or seed conflicts with the immutable receipt. Completed replay also checks current ledger ownership, remote, policy and study arm; it preserves later commits and issued capabilities. Pending forks, lost fork acknowledgments and authority eviction are recoverable with the same input. An interrupted request may leave a validated ledger and frozen receipt before the remote exists; the project is listed only after the remote is verified. All propagated error text is fixed so opaque SDK capability text cannot escape.

Verification: `pnpm exec vitest run --config tests/workers/vitest.config.ts tests/workers/campaign-provision.test.ts` — 11 passed in workerd, using real Rust repository/workspace authorities and R2. Artifacts RPC is a fixture because this local test does not invoke the remote Artifacts service. Tests cover seven independent projects, administrator/reviewer checks, immutable reuse, concurrent requests, restart, fork acknowledgment loss, pending recovery, HEAD pinning, foreign targets, invalid policy/public import, fixed errors and seeded owner study assertions without runs. TypeScript, owned Biome and diff whitespace checks passed. Initial failing tests preceded implementation and boundary fixes.

No live private repositories were provisioned by this helper during implementation, and no paid inference or deployment was performed. F owns route registration, E owns prepared campaign/study request fixtures, and the parent owns operator startup and paid campaign execution. Existing Artifact APIs were checked against [official Workers binding documentation](https://developers.cloudflare.com/artifacts/api/workers-binding/) and pinned local types.
