`commands/campaign.rs` exports `pub(super) claim_escalation(db, run, execution, now) -> Result<Option<Value>>`.

Call in second-round task scheduling or autonomous source resolver **after constructing the execution ID**, **before provider selection/job creation**, in the same ledger transaction. Exclude read-only coordinator scheduling. It reads authoritative run state, requires `team_repair_rounds == 2` and `team_repair_failure.round == 1`, a terminal cheaper failure marker with `candidate_id` or `execution_id`, and original `repair_escalation`. It atomically records `run.campaign_opus={used:true,execution_id,repair_round:2,failure,used_at}` once. Return `{provider:"claude",model:"claude-opus-5-5",harness:"claude",connection:<frozen>,budget:{provider,model},campaign_opus:true,repair_round:2}`: overlay these fields on execution before selecting provider/harness and enqueueing job. Reload persisted run for job payload after the claim so it carries original escalation approval and usage marker. Further claim attempts return None. The $5 chain/run total remains shared across Codex and Opus; Opus draws from the campaign $10 bucket. No extra repair round; no model or price changes to old runs.

B sets `team_repair_failure={round:1,model:<cheaper-model>,candidate_id?,execution_id?,evaluation_id?}` from an actually terminal failed repaired specialist/evaluation or resolver. Existing original round-zero failure evidence must never set round one. Clear/replace the marker with the evidence round at each new failure. Premium coordinator planning is prohibited.

Freeze helper receives original command `repair_escalation={version:1,provider:"claude",model:"claude-opus-5-5",connection,max_executions:1,repair_round:2,after_cheaper_repair_failure:true,budget:<finite model budget>}`. Initial `model_budgets` contains cheap scheduled group only. `campaign::freeze` verifies signed internal grant, appends the dormant Opus model group to persisted run budgets (claim grant's bound budgets contain cheap+Opus), and freezes `repair_escalation`. Existing model-budget schedule matching remains unchanged; no initial Opus agent is scheduled.
