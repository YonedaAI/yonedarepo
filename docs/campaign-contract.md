# Stream F campaign wiring (local implementation; no deploy or paid runs)

Parent owns `routes.ts`, `reviewer.ts`, app command registration and run integration.

1. In routes, after authentication/guard and before generic reviewer/owner handlers, call `campaignRoute` and `reviewerCampaignRoute`, return a non-null Response.
2. Strip `campaign`, `_campaign_grant`, `_campaign_signing_key` from generic browser owner input. Campaign start happens only inside trusted campaign handlers.
3. Register `mod campaign` in app commands and call `campaign::freeze(db, &c, &mut run, now)` after model budgets and autonomy freeze, before `create(runs)`. Advertise `campaign_budget:1`. Refresh `autonomy_approval.model_budgets` and `repair_escalation` after appending the original dormant Opus budget, before persisting any job.
4. Repository DO must REMOVE any caller `_campaign_signing_key`; for a campaign command derive its transient signing key as `yoneda_core::digest(format!("yoneda:campaign-grant:v1:{}", env.secret("VAULT_KEY")?).as_bytes())`. Inject `_campaign_signing_key` only in the transient command, never persist or log it. `campaign::freeze` verifies HMAC, exact request digest, owner/repo/run/model identity and 60-second expiry.
5. Internal callers first `campaign_bind_run` in the owning Workspace DO, then call exported `campaignGrant(env, owner, repo, approval, binding)` and send its result as `_campaign_grant` with `start_run`. Do not sign unchecked caller campaign objects.

The reviewer handler requires an existing private reviewer account, a DIFFERENT ready fullstack event-booking repository, and an already-created active `campaign-development` working branch. The parent must precreate the branch with the canonical commit/version CAS. Configuration never creates accounts, resets old spend, or starts work. Funding enablement requires successful local gates before the operator supplies `local_gate_receipt`. Configure the fresh $50 envelope FIRST (GLM evidence may be null), enable funding through `/api/admin/campaign/enable`, then start the bounded owner GLM run through `/api/admin/campaign/start_run`. Reviewer enablement through `/api/admin/reviewer/campaign/enable` additionally requires its completed independently checked GLM run ID. Funding and `reviewer_enabled` are distinct; public `campaign.enabled` combines both. Configuration seals operator-only ZAI `owner-campaign-glm-20261012` and optional Sonnet `owner-campaign-sonnet-20261012` connections, plus reviewer Codex and dormant second-repair Opus connections. No key is returned.

## Frontend / CLI contract

- `GET /api/reviewer/campaign`: JSON `null` if never configured. Otherwise `{campaign,approval,campaign_id,enabled,version,revision,expires,repo_id,working_branch_id,active_trial,active_trial_state,budget,latest_checked}`. `active_trial_state` is `reserved`, `running` or null. Budget `{limit_microusd,charged_microusd,buckets:{routine,opus,reserve},charged:{routine,opus,reserve}}`. Ceiling 50M, buckets 35M/10M/5M microdollars. Immutable approval carries `profile:reviewer-event-booking-v1`, `entry:{repo_id,working_branch_id,glm_evidence_run_id,default:latest_checked_final,coding_plan:owner_only,optional_execution:metered_codex}`.
- `GET /api/reviewer/campaign/checked`: newest completed checked FINAL result `{repo_id,run_id,candidate_id,evaluation_id,revision,url}`, or null. No inference. Read `site_preview?evaluation=<evaluation_id>` on that repository to obtain the isolated app URL. A specialist candidate does not qualify as collaborative final.
- `POST /api/reviewer/campaign/trial` body `{request_id:<stable16..64alnum-hyphen>}`: explicit optional metered execution, returns `{repo_id,run_id,campaign_id,url}`. Multi-agent collaboration, approved goal, bounded autonomy (2 repair rounds/3 concurrent/20 executions), one shared Codex budget and $5 per run, precreated branch with frozen expected working commit/version. The same original approval includes one automatic Opus5.5 source repair/resolver execution after cheaper first-repair failure, within shared round two and the same $5 chain ceiling. Opus charges its $10 bucket, and the broker fences every request to the claimed execution ID. No browser prompts, models, branches, budget or campaign fields accepted.
- `POST /api/reviewer/campaign/resume` body `{}`: resume same durable approval/run ID, including when `start_run` acknowledgement was lost. Never reinterpret its branch/approval or release a missing run.
- Disabled/unconfigured campaigns cannot execute. Default entry is read-only latest checked final after enabled. Preserve old recorded runs and historical trials; do not fall back to legacy paid start.
- Operator POST `/api/admin/reviewer/campaign/configure|enable|disable`, body `username` existing account. Configure also `repo_id,glm_evidence_run_id?(nullable),expected_version,version`; enable/disable `expected_version,expected_revision`, enable additionally `local_gate_receipt,glm_evidence_run_id` (or prior verified evidence). Verified GLM identity is stored in campaign lifecycle state without editing the immutable funding approval.

## Controlled maintenance campaign (stream E; independent from reviewer $50)

Admin POST `/api/admin/campaign/configure|enable|disable|status|bind_run|run_status`; every body contains existing account `username`. Workspace executes atomically on existing workspace records, so no app 0013/0014 or workspace migration is needed.

Configure `{id:<fresh-id>,expected_version:0,approval:{version:1,audience:owner,repo_ids:[six repos],expires:<ms>,limit_microusd:12000000,chain_limit_microusd:2000000,buckets:{routine:12000000,opus:0,reserve:0},model_budgets:[single frozen budget]}}`. Enable `{id,expected_version:1,expected_revision:1,local_gate_receipt}`. Status `{id}` returns state plus immutable `approval` and `chains:[{id,charged_microusd,models:{"provider/model":{requests,charged_microusd}}}]`. Bind `{id,version:1,repo_id,run_id,chain_id:<same three stages>,bucket:routine,purpose:routine,model_budgets:[same frozen budget]}`. Trusted `start_run.campaign` is `{id,version:1,chain_id,bucket:routine,purpose:routine}` plus internal signed grant. All three stages share requests and spend; six chains share total $12. No escalation.


## Private project provision and start

`POST /api/admin/campaign/provision` body `{username,repo_id,template,policy,context_study?,context_seed?}` calls C's bounded private Artifacts fork helper, initializes repository ownership to the existing account and reserves/marks its workspace project ready. Template is an existing private Artifacts name. Response `{username,repo_id,status,commit,source:{namespace,name,branch,commit}}`; no grants, keys or inference. Precreate `campaign-development` using the parent branch CAS command after provision.

`POST /api/admin/campaign/start_run` body `{username,repo_id,approval:<exact run command without op>}` checks repository capabilities, atomically binds campaign/workspace model budgets, signs a short-lived exact grant and starts the run. Response is the ledger's ordinary run result. Read `/api/admin/campaign/run_status` for immutable binding readback. Only this operator route and the fixed reviewer trial can mint grants; generic browser commands discard authority fields.

Pricing and usage basis: [current official model pricing](campaign-model-pricing.md). Campaign charges are conservative approval/reservation accounting; they are not a claim of measured provider invoices. Lost or incomplete usage retains the full reservation.
