# Presenter first draft

Editorial working draft adapted from the released narration. Use [the final script](presenter-script.md) for production. The historical release facts below are superseded where the final script describes the current interface.

YonedaRepo : build together, keep the why

YonedaRepo is a context graph platform for the agentic era, built on Cloudflare Workers and Artifacts. The unit of work is a shared intent with competing implementations and a traceable shipping decision. This Garden website was built by two real agents working concurrently. Both produced code and context, independent evaluators checked their captured revisions, and the owner's chosen approach became the published website. This video uses actual browser captures and recorded run evidence, edited for clarity, with synthetic narration. I will follow the developer workflow, inspect a failure that improved the next run, and show how a fresh local agent continues from the preserved context.

A personal workspace and your own agent credentials

A developer opens the website and signs up with a username and password. The account receives a one-time recovery code to save privately. There is no owner token required for normal users. In Agent providers, the developer connects their own OpenAI, Anthropic, MiMo or ZAI key. The server encrypts that key; containers use a scoped provider proxy. A user can also keep inference on their own machine and connect a local coding agent with a repository key. Add repository creates a real Artifacts fork of the website starter, or imports an allowed public Git repository. A new personal account and its isolated contribution path were exercised against the deployed platform.

Approve one brief, explore multiple approaches

New run is where the developer says what to build, sets acceptance criteria, and chooses two approaches. They can use the same provider twice or compare different providers. Existing context can be selected into the brief. The approved command profile controls independent verification and static output; candidates cannot replace that policy. The starter check is deliberately a smoke test, so meaningful project tests should be added. Approving the brief starts the agents concurrently from the same source revision and frozen context. Here, Luna pursued a botanical editorial design and Sonnet a compact community noticeboard. Each agent had a separate execution and isolated source fork, so they could work at the same time without overwriting one another.

Measured concurrency, distinct captured revisions

The concurrency claim comes from durable runtime events. Both executions reached harness running and later registered trusted transcripts at epoch one. Their measured overlap was eighty-seven point one one seven seconds. This is overlapping agent execution, rather than queued work or cold starts. The platform records the configured model, attempt identity and evidence. When an agent reports completion, a separate capture job validates regular files and constructs fresh Git objects. Luna's captured commit begins zero c forty-four; Sonnet's begins three e eighty-four. A completion message does not make either approach eligible or publishable. Independent evaluation checks the exact captured revision in a clean execution environment, then records the check policy, results and bounded static asset manifest.

A failed interaction became reusable context

An earlier candidate passed the HTML and anchor checks, but browser review found that choosing an event category did not actually hide the other cards. I kept that failure as a typed finding instead of erasing it. The next approved run received the finding as frozen context. Both agents recorded requirements and alternatives that referred to it, and implemented filtering that visibly hides nonmatching cards. This distinction matters: agent-authored requirements are assertions, and a green HTML check is limited evidence. The graph preserves where a statement came from and which later work used it. It does not turn an agent's confident explanation into a verified fact. Browser checks then confirmed filtering, restoration of all cards and the local RSVP confirmation.

The owner reviews; the engine publishes

The website presents checked approaches for review. The developer compares previews, changes, checks and context, then selects an eligible approach and records the tradeoff. Agents do not have a direct publication tool. For this run, the owner chose Sonnet in the implementation conversation; the implementer entered that explicit choice through the actual website and recorded the provenance. Sonnet had upcoming October and November dates, while Luna's otherwise polished alternative listed May dates. The publisher checks ancestry, uses an expected-old Git lease, and reads back canonical main before advancing the website pointer. The published HTML, CSS and JavaScript were compared byte for byte with the recorded R2 manifest. The isolated mobile site works, but RSVP is only an in-memory confirmation, not a real registration service.

Explore the graph from an exact source revision

Intentional history starts with an exact commit and source path. It follows the recorded decision, evaluated candidate, alternative approaches and original intent. The graph also contains typed requirements, constraints, assumptions, findings, questions and proposed decisions, with relations such as supports, challenges and supersedes. Search and type filters narrow the graph; expanding a record follows its relationships. This preserves discarded approaches and their tradeoffs alongside the chosen source. A future developer can ask why this code exists and see the supporting evidence, rather than reconstructing a conversation from scattered logs. Live notifications are only resynchronization hints. Private payloads are fetched through authenticated scope checks, so recovering an account revokes access rather than leaving an old socket with continued private updates.

A fresh local agent continues through MCP and Git

The second route is for developers already using a local coding agent. Connect local agent creates a revocable repository-scoped key, with read or contribute permission. Remote MCP exposes context, history and evidence, and the Git broker exposes canonical reads plus an isolated contribution fork. In the live test, one local Codex process built Field Notes Club, pushed its fork and submitted source for normal capture and evaluation. That first publication was explicitly marked automated development verification. A completely fresh process then queried the original intent, source history, decision and check artifact. It understood that real membership signup was outside the original static scope, changed the misleading signup copy to an honest coming-soon message, and recorded a finding superseding the old assumption. Its fresh captured follow-up passed checks and waits for owner review.

Rust domain rules on Cloudflare infrastructure

Rust owns contracts, domain commands, durable state transitions, source capture and evaluation. The TypeScript layer is the browser and a thin adapter for Cloudflare SDK capabilities. The Repo Durable Object's SQLite ledger is authoritative: state, graph changes, ordered events and outbox commit together. D1 discovery and Live notifications are rebuildable projections. Queues drive isolated container jobs with idempotency, leases and attempt epochs. Artifacts stores real Git repositories and forks; R2 stores immutable evidence and static manifests. A separate sites Worker serves untrusted output with an opaque sandbox origin, blocked outbound connections and no platform session cookie. The local gate uses native SQLite and actual workerd tests without paid inference. Cloudflare deployment and live provider acceptance are recorded as separate evidence.

Try the MVP; inspect the evidence and limits

The repository is Apache licensed, with setup commands, deployment instructions, MCP configuration and machine-readable release evidence. The local gate passed seventy-one native Rust tests and thirty-five workerd tests; the Linux runtime passed sixteen tests as root and as an ordinary user. The durable Claude allowance held eight dollars fourteen cents under the twenty-dollar cap, without increasing it. MiMo lacked balance and ZAI did not complete in time; no successful live results are claimed for them. Hosted inference used operator Secrets Store keys, while personal BYOK egress has local coverage but no live inference acceptance yet. This release hosts relative-path static sites. Full-stack execution and interactive questions that pause and resume runs are future capabilities. Today, users can build concurrent alternatives, choose a checked revision, publish it, and preserve enough context for a fresh agent to continue.
